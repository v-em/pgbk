# План развития

Текущая версия не содержит UI/API-сервера. Будущий необязательный UI может аутентифицировать оператора, показывать уже сконфигурированные targets/profiles PostgreSQL и запускать ручной backup по ID профиля через существующий путь immutable CronJob → Job. Он должен показывать статус и очищенные логи. UI не должен принимать произвольные credentials подключения или создавать второй движок резервирования. До разработки нужно определить аутентификацию/авторизацию, allowlist профилей, ограниченные права создания Job, аудит, идемпотентность запуска и отмену. Граница интеграции — существующие команды CLI запуска/статуса и стабильные ID профилей; для записи этого плана дополнительные RBAC не требуются.

Инкрементальные physical backup и PITR остаются отдельным будущим этапом: версионированные метаданные цепочек/WAL, retention с учётом зависимостей и автономная проверка восстановления. Настройки 0.2 не обещают эти возможности.
