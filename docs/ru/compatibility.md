Версия: 0.2.0. Дата: 2026-10-20. Это сборка разработки; полная приёмка версии 1 не завершена. Живые тесты Yandex пользователь выполняет отдельно. Точные версии — в [compatibility.json](../compatibility.json); отчёты — в [tests/reports](../../tests/reports). [Реестр приёмки](../../tests/reports/acceptance.json) связывает каждое требование и тест с реализацией, подтверждёнными частями и оставшейся сертификацией. Реальные интеграционные отчёты 14–18 охватывают две базы с буквальными именами, ограниченную роль дампа, таблицы по 10000 строк, wildcard/кавычки/Unicode, секции, дополнительный tablespace, отказ RLS, лимит исходных строк, пустую выборку, отмену блокирующего запроса, точную выборку со снимком, нативное и продуктовое logical restore, physical restore с остановленным источником и оба автономных drill. Отчёты Kubernetes подтверждают реальные конфликт/освобождение Lease, неизменяемую конфигурацию, создание/отмену ручного Job, фактические ограничения ServiceAccount и установку с существующими аккаунтами/Lease без изменения RBAC. API-стенд arm64 не подтверждает выполнение Job amd64.

Локальные проверки PostgreSQL 17.11 на 1 и 20 GiB прошли для logical и physical backup с последующим восстановлением при остановленном источнике. Отчёты содержат версии утилит, время, пики scratch и RSS. Тест на 20 GiB выполнялся в контейнере с 2 CPU и 4 GiB RAM: наблюдаемый пик scratch — 42,04 GiB, суммарного RSS процессов — 0,97 GiB. Fixture хранится без сжатия PostgreSQL, но содержит хорошо сжимаемый повторяющийся текст. Docker Desktop эмулирует amd64 на macOS arm64; Moto работает вне измеряемого контейнера, Kubernetes заменён fixture. Это локальные измерения объёма и корректности, а не гарантии production throughput. Первая попытка большого объекта столкнулась с лимитом HTTP-буфера macOS/Moto и не опубликовала marker завершения physical backup; успешный повтор использует порционную отправку в тестовом сервере. Отрицательные NetworkPolicy/TLS fixture, реальные отказы/освобождение PVC, изоляция узлов/разрыв API, promotion, конкурентные DDL/записи, globals/большие объекты/полнота зависимостей и полные проверки ротации/утечек остаются работой приёмки release. Реализация безопасного отказа не заменяет отсутствующие подтверждения окружения/тестов.

## Повторение проверок разработки

Запустите Moto в отдельном терминале только с синтетическими учётными данными, затем подготовьте одноразовый bucket pgbk-test. Не направляйте fixture-скрипты в production: harness создаёт синтетические базы и использует отдельные integration-префиксы.

```sh
uv sync --frozen --group integration
uv run --frozen --group integration python -m pytest
uv run --frozen --group integration python scripts/check_docs.py
helm lint charts/pgbk -f examples/values.yaml
uv run --frozen --group integration moto_server -H 0.0.0.0 -p 19000
```

```sh
uv run --frozen --group integration python tests/feasibility/bucket.py
python3 scripts/build_images.py
python3 scripts/run_integration.py
python3 scripts/evidence.py
```

Для Docker Linux нужен host.docker.internal:host-gateway; runner добавляет его автоматически. Kubernetes smoke использует отдельно созданный kind-кластер и удаляет временные namespace. CI выполняет зафиксированные unit/chart-проверки и ту же реальную матрицу 14–18, не публикуя образы и не выполняя живых действий провайдеров.

## Обновление и артефакты

До обновления сохраните проверенную скачиваемую копию и среду восстановления соответствующей основной версии. Сборку и публикацию образов выполняйте своим registry-процессом, записывая реальные registry digest и обновляя values/images. Docker image config ID не заменяет digest registry-манифеста. Новые immutable ConfigMap применяются только к новым Job; запущенные сохраняют прежнюю ссылку. Проекции Secret управляются извне и могут изменяться во время запуска, поэтому выполняйте ротацию между запусками. Сохранённые Lease нельзя сбрасывать при upgrade/rollback; общие заранее созданные Lease требуют coordination.createLeases=false. Стабильные installationId/sourceId/profileId/prefix сохраняют идентичность каталога. Их изменение выбирает другой каталог, а не выполняет миграцию.

Wheel/source archive CLI, Helm package, сведения об образах, checksums, CycloneDX SBOM и уведомления о сторонних компонентах создаются в dist. Исходный код лицензирован Apache-2.0. PostgreSQL/WAL-G/Python/OS и Python-зависимости сохраняют собственные лицензии; copyright Debian и тексты лицензий пакетов сохраняются/извлекаются. Обогащение Go-лицензий и неизвестные записи SBOM требуют окончательного аудита до сертификации распространения; результат сканера не является юридическим заключением. Базы PostgreSQL/WAL-G/Python-зависимости зафиксированы, но apt-репозитории и время сборки не заморожены для побитового повторения. Продвигайте проверенный образ по immutable registry digest, не пересобирая его при установке.

## Приёмка Yandex оператором

Используйте заранее созданные изолированные источники/назначения/префиксы bucket и учётные данные, поступающие извне. Выполните T-001–T-004, T-024, T-028, T-030–T-032 и T-035 из [плана тестирования](test-plan.md): backup, удалённую SHA-проверку, скачивание, восстановление при недоступном источнике, drill, отказы доступа/TLS и ограниченный retention. Сохраните версии утилит/образов/chart, run ID, точный endpoint провайдера, ожидаемые данные и обезличенные отчёты времени/ресурсов. Удаляйте только свои временные префиксы/claim после подтверждения отсутствия writer. Репозиторий не выполняет живые тесты Yandex и не сертифицирует их по результатам эмулятора.

Отчёты от 2026-10-11 — историческая база 0.1. Проверки режимов 0.2 записываются отдельно в tests/reports/modes-*.json. Прежние license/SBOM-артефакты не подтверждают новую сборку.
