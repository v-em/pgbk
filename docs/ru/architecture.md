# Решение реализации — ADR-001

Версия: 0.2.0. Дата: 2026-10-20.

Исполнитель разрабатывается на Python 3.11+ вместо предложенного Go. REQ-035 допускает выбор языка на M0 через двуязычное архитектурное решение. Python предоставляет upstream-парсер AST PostgreSQL (pglast), координацию снимков psycopg, официальный клиент Kubernetes и boto3. Средства резервирования остаются отдельными процессами; передача и хеширование артефактов идут с диска потоково. Python не хранит целую копию в памяти. Решение предварительное до прохождения всех проверок M0 и выпуска; требования к доступу к источнику, артефактам и координации сохраняются.

Репозиторий содержит реализацию и исполняемые тесты. Локальные доказательства реализуемости используют PostgreSQL и WAL-G в контейнерах Linux amd64 и S3-эмулятор Moto с лицензией Apache-2.0. Результаты эмулятора подтверждают только поведение адаптера; сертификацию Yandex оператор выполняет отдельно. Готовность к production также требует реальных проверок S3/managed-провайдера, Kubernetes/PVC, TLS, переключения источника, внедрения отказов и ёмкости из плана приёмки. Недоступные среды остаются `not-run` или `blocked`.

Временное хранилище использует ограниченный emptyDir, generic ephemeral PVC Kubernetes, принадлежащий Pod, либо явно разрешённый выделенный PVC. Leases создаются заранее и никогда не захватываются у другого владельца, даже после истечения. Для потерянного владельца оператор должен сначала гарантированно остановить прежние процессы. Lease репозитория последовательно выполняет публикацию, скачивание, восстановление, проверку и очистку; его владелец служит устойчивым закреплением копии. Последний публикуемый объект — маркер завершения со ссылкой на канонический неизменяемый манифест. Проверка целого объекта всегда скачивает его и вычисляет хеш, независимо от ETag и необязательных checksum провайдера.

Физическая копия содержит upstream tar-файлы данных/WAL/tablespaces и манифест PostgreSQL. Проверка использует изолированную распаковку; восстановление пересоздаёт только явно сопоставленные ссылки tablespaces и заменяет исходную конфигурацию PostgreSQL безопасными настройками изоляции. Продукт не использует PVC или контейнеры источника.

Logical 0.2 поддерживает custom/direct через SDK multipart и custom/directory со staged-передачей WAL-G. Directory упаковывается из обычных файлов и безопасно распаковывается при restore. См. [режимы](logical-modes.md). Будущий необязательный UI использует существующий запуск по ID профиля; см. [план](roadmap.md).
