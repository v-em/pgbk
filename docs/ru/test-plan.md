## 1. Тестовые среды и доказательства

Тестовая система заранее создаёт временные PostgreSQL и настраивает их права. Подготовка источника — задача тестовой системы, а не продукта. Реальные production-данные в тестах запрещены.

Обязательные среды:

- PostgreSQL 14, 15, 16, 17 и 18; исполнитель каждой версии использует утилиты соответствующей major-версии.
- Обычный Kubernetes StatefulSet и доступное фиксированное Bitnami-развёртывание; в результатах записываются происхождение и лицензии чарта/образов. Если воспроизводимый распространяемый Bitnami-образ недоступен, интеграция помечается непроверенной, а не незаметно заменяется другим образом.
- Ограниченная non-superuser среда, имитирующая managed-условия, и минимум один smoke-тест реального managed PostgreSQL до заявления сертификации провайдера. Записывается проверенный провайдер/версия; эмуляция не равна сертификации.
- Открытый S3-совместимый тестовый сервер для обычного CI и реальный бакет Yandex Object Storage для сертификации выпуска. Тесты изолированы уникальными временными префиксами.
- kind или аналогичный Kubernetes: заявленная минимальная и актуальная поддерживаемая версии; дополнительно кластер с соответствующим production StorageClass для сертификации lifecycle PVC.
- TLS-наборы: корректный CA, неизвестный CA, просроченный сертификат, неверное имя хоста, необязательный клиентский сертификат.

Данные включают минимум две базы; несколько схем; quoted/Unicode имена баз и объектов; таблицы с PK/FK/check constraints; индексы; sequences; views; large objects; partitioned tables; расширение; roles/ACL; таблицу с RLS. Физический набор включает дополнительный tablespace и WAL по отдельному пути. Нагрузка создаёт committed writes во время копирования и маркеры до, во время и после него.

В каждом отчёте: test ID, requirement IDs, версия источника, версии клиентов/WAL-G, image digests, chart/Kubernetes, S3-провайдер, seed данных, run IDs, результат, длительность и очищенные от секретов логи. Хеши/количества сравниваются с ожидаемым согласованным состоянием набора, а не меняющимся живым источником. Тесты конкурентной записи используют инварианты и transaction markers с описанной семантикой снимка.

## 6. Уровни тестирования и порядок запуска

1. **Каждое изменение:** unit tests schema, retention, состояний manifest/marker, reason codes, lock state machine и формирования argv; chart schema/lint/render; согласованность двуязычных документов.
2. **Интеграция pull request:** реальные PostgreSQL logical/physical round-trips, S3, TLS/permissions, репрезентативное восстановление и внедрение отказов изменённых компонентов. Одних поддельных subprocesses недостаточно для доказательства корректности копии.
3. **Ночью/перед выпуском:** матрица 14–18, kind lifecycle/concurrency, failover, большие наборы, полные restore drills, расширенные проверки безопасности и ошибок.
4. **Release candidate:** все обязательные тесты и отдельно разрешённые живые провайдеры, включая Yandex и managed PostgreSQL. Используются заранее предоставленные ресурсы либо явно одобренные временные ресурсы с очисткой и лимитами расходов; credentials передаются средой.

Отсутствие условий не означает прохождение. Различать `passed`, `failed`, `blocked`, `not-run`, сохранять диагностику и объяснять пропущенную сертификацию провайдеров. Документ определяет будущие тесты; проверка Markdown и совпадения IDs не означает, что приложение прошло тестирование.

## 7. Проверки перед выпуском

- Решения M0 документированы с точными версиями и доказательствами.
- Покрыты REQ-001–REQ-042; для каждого T-001–T-045 записан результат.
- Оба типа восстанавливаются только из артефактов S3 и совместимой целевой среды.
- Не обнаружены административные изменения источника, утечки, незащищённая публикация или удаление вне области.
- Helm package, worker images, CLI и контрольные суммы воспроизводимы и версионированы.
- Английские и русские документы соответствуют поставленным настройкам и командам.
- Любой дефект, способный повредить копию, показать неполную копию пригодной, удалить защищённые копии или изменить источник, блокирует выпуск.
